# Design direction — the developer’s sketchbook

The owner's uploaded Hand-Drawn design brief sets the current direction. It replaces the earlier serif portfolio with warm paper, marker headings, handwritten notes, organic borders, hard offset shadows, paper tape, small rotations, and red, blue, and yellow accents. The result is implemented in the existing semantic HTML/CSS/JavaScript stack; reference examples written for React or Tailwind do not require adding either dependency.

## System and layout

`styles.css` centralizes the palette, two reusable irregular border radii, an organic round shape, and two hard shadow sizes. Kalam 700 and Patrick Hand 400 are self-hosted with their OFL licenses. The page loads two Latin font files instead of three. Unused Instrument Serif and Manrope assets and the old font package are removed.

The cover pairs large marker lettering with a taped yellow portrait sheet and the existing neutral-clothing 3D developer. Selected work is a paginated notebook: one full-width project at a time, with original concept artwork, scope notes, tags, and case-study links. Two small paper edges suggest the remaining pages. Native scroll steps advance and reverse the notebook while CSS sticky keeps it in view, releasing into the archive after the final project. Numbered controls, previous/next buttons, keyboard navigation, and horizontal touch swipes synchronize to the same scroll steps. A compact mobile layout retains the project title, full summary, and case-study action; category and technology details remain in the case study. Short viewports that cannot fit the notebook use manual pagination and the full reading layout. The archive is a quieter notebook index with filters. About uses a taped letter and three capability notes; experience uses connected dots; contact is a yellow note with a drawn arrow. The résumé follows the same typography and paper palette and remains printable.

The main column is limited to 1024 pixels. Grids stack on small screens, handwritten copy remains readable, and controls retain touch targets of at least 48 pixels. Decorations are hidden from assistive technology. Red marker fills use dark text; small red annotations use a darker red ink token for contrast. The site adds no fictitious metrics, awards, public product links, or shipment claims.

## Motion

Native CSS View Timelines drive modest content arrivals, artwork parallax, a tracing journey line, a reversible cover underline, and the contact arrow. Scrolling backward restores the same states. JavaScript supplies finite heading introductions, bounded direction-aware hover, a repeating IntersectionObserver fallback, and user-triggered page transitions. Page changes combine a short directional slide with a small paper rotation. Inactive pages are hidden and inert; the outgoing page is visual only. Rapid requests cancel previous transitions and settle on the latest selection. Width and font changes trigger a batched height measurement, avoiding shifts between projects. Hover geometry is remeasured on departure and pointer cancellation clears the effect. Buttons press down with reduced hard shadows.

Reduced motion, manual pause, keyboard focus, no JavaScript, Data Saver, and WebGL failure retain readable content. The optional renderer stays independent of content and is deferred until after the heading introduction. The user-requested scroll notebook uses a bounded CSS sticky region and IntersectionObserver landmarks; it never cancels wheel or vertical touch input. Manual page choices move the native document to the matching step. There is no scroll hijacking, perpetual decorative loop, or JavaScript scroll-position polling.
